# n8n-nodes-max-messenger

Ноды [n8n](https://n8n.io) для Bot API мессенджера [MAX](https://max.ru): сообщения с кнопками, файлами и форматированием, управление чатами и каналами, запуск сценариев по сообщениям и нажатиям кнопок.

> Неофициальная нода сообщества. Не связана с MAX и VK.

В пакете две ноды:

- **MAX**: сообщения, чаты, настройки бота, видео. Подключается к AI Agent как инструмент.
- **MAX Trigger**: запускает сценарий по событиям бота. Сам регистрирует и снимает вебхук в MAX.

Подробная документация на английском: [README.md](README.md).

## Установка

- **Из панели нод** (n8n Cloud и self-hosted с проверенными нодами): найдите «MAX» и нажмите Install.
- **Self-hosted вручную:** *Settings → Community Nodes → Install*, имя пакета `n8n-nodes-max-messenger`.

## Учётные данные

Создайте бота на [business.max.ru](https://business.max.ru) (*Чат-боты → бот → Настройки*) и скопируйте токен. В n8n создайте учётные данные **MAX Bot API**:

- **Access Token:** токен бота.
- **API Domain:** **Automatic** (по умолчанию) — нода работает с `platform-api2.max.ru`, который MAX требует с июля 2026, а если n8n не доверяет его сертификату, переходит на старый `platform-api.max.ru`. Можно выбрать домен и вручную.
- **Ignore SSL Issues:** не включайте, с Automatic не нужно.

### Сертификат Минцифры

У `platform-api2.max.ru` сертификат от Russian Trusted Root CA, которому большинство установок n8n не доверяет. С доменом **Automatic** ничего делать не нужно: нода сама перейдёт на `platform-api.max.ru`, проверка сертификата при этом остаётся. Если выбрать `platform-api2.max.ru` вручную, а n8n ему не доверяет, нода пишет *«TLS certificate of the MAX API is not trusted»*. Варианты:

1. **Добавить сертификат.** Скачайте `russian_trusted_root_ca.cer` и `russian_trusted_sub_ca.cer` с [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt), соберите в один PEM и передайте n8n через `NODE_EXTRA_CA_CERTS`:

   ```bash
   mkdir -p certs
   (cat russian_trusted_root_ca.cer; echo; cat russian_trusted_sub_ca.cer; echo) | tr -d '\r' | sed '/^$/d' > certs/russian-ca.pem
   docker run ... -v "$PWD/certs:/certs:ro" -e NODE_EXTRA_CA_CERTS=/certs/russian-ca.pem docker.n8n.io/n8nio/n8n
   ```

   Каждый сертификат в файле должен заканчиваться переводом строки, иначе Node.js файл проигнорирует.
2. **Выбрать в учётных данных Automatic** (или старый домен).
3. **Включить «Ignore SSL Issues»**: проверка сертификата отключится только для запросов к MAX.

## Что умеет нода MAX

- **Сообщения:**
  - отправка: текст, Markdown, HTML, вложения, клавиатура, ответ, пересылка; текст длиннее 4000 символов делится на несколько сообщений;
  - правка, удаление, получение одного сообщения или списка (с Return All по всей истории);
  - ответ на нажатие кнопки.
- **Чаты:**
  - информация о чате;
  - смена названия и описания;
  - статус «печатает…»;
  - закреп;
  - участники и администраторы;
  - удаление участника;
  - выход бота из чата.

  Закреп, участники и правка чата работают только в группах и каналах.

  Права бота в группе: сделайте бота администратором. «Читать сообщения» нужно для событий из группы, получения сообщений, закрепа и списков участников, «Закреплять сообщения» — для закрепа, «Изменять чат» — для смены названия и описания, «Добавлять и удалять участников» — для удаления участника. Без прав MAX отвечает *«Insufficient permissions in chat»*.
- **Бот:** информация о боте, команды меню.
- **Видео:** ссылки на воспроизведение и параметры видео.

Вложения: файл из бинарного поля, картинка по ссылке, токен уже загруженного в MAX файла (например, из входящего сообщения), стикер, геоточка. Не больше 12 штук, клавиатура считается одним из них. Картинки и видео можно сочетать, файл, аудио, стикер и геоточка отправляются поодиночке.

Тип файла определяется по MIME: JPG, PNG, GIF, TIFF, BMP и HEIC уходят картинками, MP4, MOV, MKV и WEBM видео, остальное (WebP, SVG, PDF…) файлом. Во время загрузки нода держит файл в памяти, поэтому предел размера на практике зависит от памяти сервера n8n.

Кнопки собираются по одной (ряд, тип, текст) или передаются JSON. Типы: callback, ссылка, отправить сообщение, запрос контакта, запрос геопозиции, копирование в буфер, мини-приложение.

## MAX Trigger

Выберите события и включите сценарий. Триггер подписывает свой вебхук со случайным секретом и проверяет заголовок `X-Max-Bot-Api-Secret`: запросы без него получают 403. При выключении сценария снимается только его подписка, другие интеграции бота (CRM, другие сценарии) продолжают работать.

Если вебхук 8 часов не отвечает (n8n лежит, истёк сертификат), MAX снимает подписку сам. После такого простоя выключите и включите сценарий.

MAX доставляет события только на **публичный HTTPS-адрес на порту 443** с доверенным сертификатом, поэтому n8n должен быть доступен из интернета. В группах и каналах бот должен быть администратором с правом читать все сообщения.
